## Research and design consequences

Installed versions: OTP29.0.6/ERTS17.0.6, Elixir1.20.4, Qt6.11.2, Quickshell0.3.1. Supported CI remains OTP27/Elixir1.18, OTP28/1.19, OTP29/1.20. Baseline local gate already passed 119 ExUnit including real peers, 27 JS, 5 Python, 24 Qt results at both scales; baseline final CI passed all three combinations. No redundant untouched endurance baseline is needed.

* [OTP process_info](https://www.erlang.org/doc/apps/erts/erlang.html#process_info/2): reductions are counters; memory is bytes; mailbox is a count. Stack metadata is capped by the target's backtrace setting. Compare only same node creation and exact PID with positive monotonic spans, rejecting counter resets. Current stack samples can miss short work, include waiting, and do not measure function call counts, elapsed CPU or allocation attribution. Do not change the target's backtrace setting.
* [Recon proc_window](https://recon.hexdocs.pm/recon.html#proc_window/3): an interval snapshot is distinct from absolute rankings; short-lived processes can fall between endpoints. First-only/last-only rows are unmatched observations, never fabricated zero-baseline rates or proof of exit.
* [Recon bin_leak](https://recon.hexdocs.pm/recon.html#bin_leak/1): it actually garbage-collects processes. Do not implement automatic whole-VM GC as a supposedly observational memory diagnostic. Existing explicit single-process GC remains unchanged.
* [OTP ETS info](https://www.erlang.org/doc/apps/stdlib/ets.html#info/2): memory is target words; `id` identifies a table separately from its reusable name. Match identifier and VM incarnation, not table name. Ownership may change; explain it without claiming table replacement. Metadata is racing, not atomic, and decentralized counters can make info more expensive. Keep deadlines/caps and no table contents.
* [OTP erpc](https://www.erlang.org/doc/apps/kernel/erpc.html#call/5): remote execution can outlive caller timeout; cancellation ends helper ownership, not a guarantee of canceling remote execution. No mutation/tracing/code installation in these new workflows. Local diagnostics terminate on panel close/historical state/owner loss.
* Installed `runtime_tools-2.4/src/observer_backend.erl` lines 563–575/627–650: process census iterates processes and emits chunks, excluding its own RPC caller. Existing collector already uses it. New survey admits a maximum reported population of 10,000 before calling, caps retained rows, and labels census races. Admission is not a hard target allocation limit if the population races upward. Two deliberate census passes replace no persistent recorder state.
* [Qt performance](https://doc.qt.io/qt-6/qtquick-performance.html): use capped delegates/models and state-driven rendering. New evidence uses static proportional bars with numeric text, no animation or continuous Canvas loop. [Observer guide](https://www.erlang.org/doc/apps/observer/observer_ug.html) likewise describes sampled values, which may miss peaks.

## Scope, ownership and protocol

Add three typed asynchronous commands: `process_window`, `ets_window`, `sample_process`; request ID, admitted node, required nonnegative `expected_creation`, and an allowlisted `duration_ms` of 1000 or 5000 (UI defaults 5000). `sample_process` additionally requires a canonical exact PID. Reuse Diagnostics' 2 active/16 queued limits, one remote job per node, owner monitoring and interactive cancellation. No timers when no request is active. Add explicit cancellation by request ID, owner-scoped, so Cancel stops only the chosen diagnostic. Keep/Revert remains independent.

A shared pure comparison module projects allowlisted fields, matches only exact identities, distinguishes signed gauges from monotonic reduction rates, records endpoint counts/partial/omitted/unmatched rows and measured span. Process survey has two capped census passes and at most 60 emitted rows chosen fairly across the three metrics. ETS survey has at most 256 metadata rows per pass (respect lower existing config caps), returns at most 60 ranked changed/unchanged rows with omissions. Stack sampling has 250ms spacing after each observation, at most 20 samples/20 frames per stack and 40 displayed unique stacks; no arguments, paths, labels containing arbitrary application terms, dictionaries, messages, binary contents/IDs, or ETS keys/values. Identity rechecked at endpoints; a restarted or disconnected target cannot become a completed continuous comparison.

UI lives within existing Process and ETS workflows. No title, action-rail, host padding, launch route, theme or keyboard convention changes. New panel content provides Start/Cancel, pending/canceled/error/captured state, capture times, measured span/coverage, local filters/sort, exact PID/owner navigation and an explicit copyable allowlisted report. Stack bars measure sample frequency and retain text counts, not just color. A target/session/history change clears correlation handles; late results cannot overwrite a new target. Completed reports are session-only and capped by existing UI job retention. They do not silently become recorder frames or persist raw diagnostics. Existing ZIP remains its documented recorder/current-snapshot handoff; these on-demand reports can be copied deliberately.

## Acceptance criteria and limits

The operator can find the highest measured reduction rate, mailbox growth or memory growth in an admitted process scan, inspect that exact PID, sample its stacks, and inspect growing ETS owners without a remote shell or application dependency. UI reports explain missing coverage and measured units. Cumulative counters never masquerade as rates, unmatched entities never receive made-up deltas, and a named replacement never inherits an old identity. New remote work starts only on an explicit command, is cancellable, has a hard helper deadline and capped retained results, and creates no sustained background load. No trace ownership, scheduler setting, GC, state/message/table-content read or workstation customization is introduced.

Full gate remains strict (format, warnings-as-errors, ExUnit/default and real peers, Credo, Dialyzer, actual-launcher protocol). Source contracts are supplementary; production Qt tests establish component behavior, actual native captures establish installed-host presentation. All artifacts stay in private `/tmp/beam-deck-community-evidence`, never the watched source. Recheck root/branch/remote before each commit/push. No force push. Deferred features above are ranked alternatives, not promised unfinished milestones.
